# Referee review against the implementation

Astra reviewed Neon's eight proposals against the native renderer, Fable's review on main at ab22989, the saved Shadow of War captures, and the Microsoft and NVIDIA API guidance. The useful change is to distinguish local image anomalies from an incorrect scene route. The proposed threshold and placement changes are unsuitable as production defaults.

| Proposal | Decision and evidence | Useful revision |
|---|---|---|
| 1A. Foliage veto | The code enters this branch below 2% moving textured samples. Its proposed greater-than-5% condition can never hold. The proposed change would suppress the detector for all-zero vectors during a pan. Motion failure changes the preview to check_inputs when delivery is already proven. | Distinguish brightness-only changes from spatial displacement, and local animation from coherent motion across the frame. Retain the bad-zero-field control. |
| 1B. Mixed composite | Repeated mixed frames need at least two independent tile votes each way. A translucent layer can be inconclusive or can favor either source by chance. A two-to-one majority cannot tell us what happened to a reflection in the minority. The cited preview returns a diagnostic label. It does not hold the renderer. | Continue delivery through the proven scene. Compare the disagreeing region and a stable control region with registered, distinguishable pixels over several accepted presents. Treat lack of evidence as inconclusive. |
| 1C. Flat fog | EdgeCorrelation checks variance before division. Score and Window deliberately abstain on a featureless screen. The proposed test compares means of high-pass values, which approach zero for unrelated constant colors, and its condition accepts either image being flat. | Keep the last proven route during temporary lack of detail. Acquire fresh screen evidence when a distinguishing edge returns. |
| 2A. Bindless barrier | A transition declares permitted access. It cannot identify the shader that read a resource or the layer that reached the screen. Anno already uses a learned barrier. Some resources stay in a readable state, and eligible cases support implicit transitions or enhanced barriers. | Reuse barriers to nominate candidates, constrained by the actual queue, submitted order, view and subresource. Require an independent display witness before steering. |
| 2B. Split-screen motion or preset trial | Two halves contain different objects. Evaluating a shared temporal feature twice can contaminate its history. The current backend uses per-view features and disables output subrects. Two input offsets cannot create an independent hidden trial. | Use the same pixels and frames for both candidates with independent warmed histories. Prefer existing saved-capture replay first. Any later live shadow trial needs measured headroom and correct full-frame context and crop correspondence. |
| 3A. 35% motion agreement | A point is explained when its error is less than 80% of the no-motion error. The current pass requires both the aggregate error ratio and coverage. Partial already covers some working motion, without blocking delivery. No data identifies the remaining 65% as particles. | Compare errors by textured background, foreground and ambiguous regions on known-correct and known-wrong fields before proposing a threshold. |
| 3B. Tile margin 0.08 | The margin compares correlations, not raw float roundoff. At eight fixed sites on the 132 independently registered frames of six saved 30-frame sequences, output/input/inconclusive votes changed from 77/0/55 at 0.02 to 74/0/58 at 0.08. Output-favoring textured tile votes fell from 378 to 373. Both thresholds produced one input-favoring tile. This is a fixed-site sensitivity comparison, not total runtime coverage, and the archive lacks labeled bypass frames. | Retain 0.02. Calibrate against negative controls as well as genuine deliveries. The production sampler can already move some probes to pixels that distinguish the sources. |
| 4. Last depth-tested draw | This identifies a useful boundary for some direct-to-screen layouts. Battlefield 4's geometry layers, Rome II's second depth buffer, and Shadow of War's rotating lighting owners show why the rule cannot identify final scene color on its own. A depth-enabled draw can write geometry attributes or a 3D marker. Later shading can run with depth testing off. | Keep the existing depth boundary alongside reader, writer and presentation evidence. The actual pixel result decides between eligible candidates. |

The first implementation priority supported by both reviews is a regional check of mixed composites. The second is distinguishing unchanged geometry under changing illumination from genuinely missing motion. Off-screen preset or motion trials are a later, budgeted option. None of the eight snippets earns immediate adoption as written.

## What earns an implementation change

1. Reuse the existing registered screen probes for a short comparison of the disputed region and an unaffected scene region. Keep ordinary delivery throughout. The check must separate a known clear output with a translucent overlay, a small known patch of raw input over an otherwise reconstructed frame, and alternation of the entire frame. An unreadable region stays unresolved.
2. On the same static textured geometry, vary illumination and compare that against a genuine camera pan with deliberately zero motion. The former should leave motion unjudged while the latter still flags missing motion. A scene with moving foliage around stable geometry checks that local uncertainty stays local.
3. Calibrate threshold proposals against saved positives and labeled negative controls, using the same registered pixels for both values. Count wrong approvals and losses of real delivery independently.
4. Reuse Fable's saved-frame NGX replay for competing motion fields or presets. Only budget a live shadow comparison when replay demonstrates a decision the existing tests cannot make. Use the same view, corresponding pixels, equivalent warm-up, and separate histories.

- `src/core/referee.hpp` contains EdgeCorrelation, Score, Window and Judge.
- `src/core/referee_selection.hpp` contains VoteScreen, DistinguishTrialOutput and Preview. `src/host_dx12/capture/referee_gpu.cpp` emits the preview as a diagnostic.
