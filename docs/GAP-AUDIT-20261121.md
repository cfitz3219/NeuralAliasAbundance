## Referee gaps

### 4. The Referee does not control jitter: it measures vibration and wrong inputs, but only writes them down

**Cort's requirement, added 2026-11-21:** "It only measures jitter? It's supposed to control
and decide where and when to place it!" The Referee is required to own jitter placement.
Measuring it is not enough. This item is therefore a required ability that has not been
built, and it is the first thing to build after items 1 to 3.

**Where the decision sits today**

- DX12: fixed rules in `vpj_before_draw`, `src/host_dx12/observe/producers.cpp:5445`.
- DX11: fixed rules in `src/host_dx12/native11/viewport_jitter.hpp`.
- Neither reads anything from the Referee. The `b75bf44` change (restore the game's raster
  for layers after a native resolve) is also a fixed rule and works with the Referee off.

**What the Referee does today**

- Measures vibration (`JitterVibration`) and logs it as `referee_jitter_geometry`
  (`src/host_dx12/capture/referee_gpu.cpp` 520 to 538). Nothing reads that number back.
- Detects wrong jitter sense and half or twice motion (`src/core/referee.hpp` 549 to 563),
  but `check_inputs` is only printed as `referee_choice mode=preview`
  (`referee_gpu.cpp` 361 to 372). No trial follows.
- The Composition stage has one tool, Sharpen (`src/core/referee_recovery.hpp` 24 to 43).
  There is no jitter tool at all.

**Suggested fix**

- The Referee owns jitter placement as one shared policy in the shared core (`src/core`)
  for both APIs. "Where" means which draws and layers receive jitter. "When" means under
  which frame conditions and by how much. The hooks only carry out the decision and report
  what happened.
- Every change is proved on screen with the existing trial (Baseline, Candidate,
  ConfirmBaseline) and rolled back when it harms the picture.
- First step: make vibration a trial symptom, with tools the Referee can choose from
  (restore the game's raster for post-DLAA layers, depth twin, jitter amount).
- Turn `check_inputs` into a short trial so that a wrong jitter sense is corrected.

### 5. The Referee is off by default and hidden

- `src/host_dx12/settings.hpp:155`: `referee_enabled{0}`.
- The menu row exists only when built with `NA_REFEREE_MENU=ON` (`CMakeLists.txt:45`,
  default OFF). `build.ps1` and the install scripts do not set it.
- Every repair is gated on that switch: `j2/live_dlaa.cpp` 517, 4532, 5392, 8785 and
  `native_d3d11/live_dlaa.cpp` 461, 1069.
- **Affects:** a normal build has no Referee, and Cort cannot turn it on from Home.
- **Suggested fix:** decide the default deliberately; if it stays off, give it a Home row
  in normal builds.

### 6. A rejected trial is rejected for the rest of the session

`src/core/referee_trial.hpp`:

- `CanStart` (line 244) only restarts a trial when `retry_at_` is set.
- Plain `Reject` at line 428 ("the original flicker did not return consistently"), 454 and
  467 ("an isolated change prevented a reliable verdict") never sets it.
- **Affects:** one unlucky window (a cutscene, a camera cut) removes a repair until the
  game is restarted.
- **Suggested fix:** retry after a scene change or a time, with a small limit. Sol owns
  this policy.

### 7. The Referee cannot see small flicker

- `kThumbW=128, kThumbH=72, kThumbTaps=4` (`src/core/referee.hpp` 35 to 36, 98 to 110).
  At 3440x1440 that is one tap per roughly 7x5 pixels.
- A region is 1/64 of the screen and the threshold is 0.12 stops
  (`src/core/referee_trial.hpp:177`).
- **Affects:** thin-line shimmer and small distant lights can average away below the
  threshold, so the Referee reports a steady picture while the player sees flicker.
- **Suggested fix:** a second, full-resolution look at the worst region only.

### 11. Trial timeouts do not name the blocking gate

- `src/core/referee_trial.hpp`: silent drops at 290 to 293, 304 to 308 and 415 to 421; one
  generic reason at 269.
- **Affects:** the results log says a trial ended, not why (Cort's rule: logs say WHY).
- **Suggested fix:** record the last gate that refused, and print it with the verdict.

### 12. The Referee covers added DLAA only

- `j2/live_dlaa.cpp:5102`, `native_d3d11/live_dlaa.cpp:862`, and
  `capture/j2_capture.cpp:381`: `if (id.presentation_only || id.owns_present) return 0;`.
- **Affects:** Route A (games that ship DLSS), added upscaling and the 32-bit companion
  get no Referee.
- **Suggested fix:** widen after item 4, one route at a time.

## NeuralAlias gaps

### 8. No frame-time watcher

- The only budget is a vertex budget (`src/core/replay_budget.hpp`).
- **Affects:** Cort's 40 to 50 fps floor is not measured or defended by the program.
- **Suggested fix:** one frame-time watcher that the Referee can read as a symptom.

### 9. No memory between launches

- Referee scopes are keyed by memory addresses (`src/core/referee_placement.hpp` 11 to 18),
  which change every launch.
- `profiles/layout_cache.hpp` is referenced only by `tests/cpu/layout_cache_test.cpp`.
- **Affects:** every launch relearns everything; proved roles are lost on exit.
- **Suggested fix:** key by stable content (shader and format fingerprints) and save per game.

### 13. DLSS input flags are guessed

- HDR is decided by float format alone (`j2/live_dlaa.cpp` 1980 to 1984, 5034;
  `native_d3d11/live_dlaa.cpp:418`; note in `dlss/dlss_backend.cpp` 106 to 108).
- Auto exposure is always on for DX12 (`j2/live_dlaa.cpp:5037`) but follows HDR on DX11
  (`eval.hdr = eval.auto_exposure = hdr`, `native_d3d11/live_dlaa.cpp:778`).
- The bias mask is used only for the HUD (`j2/live_dlaa.cpp` 5059, 8039).
- **Affects:** wrong brightness handling or ghosting on particles in some games; the two
  APIs can disagree on the same game.
- **Suggested fix:** one shared rule; let the Referee test the flag when the picture verdict
  is poor.

### 14. Standing-rule breaches

- Game name in code: `host_boot/host_boot.cpp:328`
  `lstrcmpiW(scene_camera_exe, L"s2_sp64_ship.exe")`; `adapters/wwii/scene_camera.hpp` used
  from `native11/provider.cpp` 448, 724 and `j2/live_dlaa.cpp` 3436.
- Driver app named in the UI: "NVIDIA app" in `overlay/route_a_panel.cpp` 246, 337, 338.
- A setting that needs a restart: Frame Generation preset (`overlay/route_a_panel.cpp:653`,
  `settings.hpp:179`).

### 15. Structure

- `j2/live_dlaa.cpp` is 9,704 lines (598 KB), `observe/producers.cpp` 10,007 lines (538 KB),
  `native11/provider.cpp` 3,800 lines.
- **Affects:** the same fix is written once for DX12 and once for DX11 (Cort's ONE program
  rule); item 4's shared jitter policy is the natural first piece to pull into `src/core`.
