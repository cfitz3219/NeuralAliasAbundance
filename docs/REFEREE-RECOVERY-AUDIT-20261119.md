# Referee proof and recovery audit

The original review below records the November 19 behavior. The [November 21 decision table](#november-21-update--what-happens-next-during-play) includes the subsequently implemented motion-input and placement trials.

This review covers the native DLAA paths and their shared picture, delivery, motion and jitter checks. It follows up the rotating lighting fix at e1d2db6. The latest available Shadow of War captures used 2e062ef. They show alternating scene input and local warping that first appears in K's output. The recordings contain one of the two lighting buffers at any sampled evaluation. The replay work in Fable's branch tests the output-side warp separately.

## What the Referee should look for

| Failure seen in development | Evidence to look for | Runtime response and remaining work |
|---|---|---|
| A decoy, unreadable bindless compositor or ordinal that moves when the draw order changes | Executed writers and actual consumers followed by a challenge on the exact final image. Require independent regional codes so genuine light strobe cannot answer the challenge. | DX11 and DX12 reuse the three-region code. Confirmed readers steer their own route. A candidate that stops appearing yields the probe. DX12 marks retain their submission leases. A frame assembled through an unobserved queue or consumer needs more evidence. |
| Alternating early and fully lit HDR buffers | A recurring completed draw order with matching depth and independent displayed evidence for each physical buffer. A current-frame write must match the active viewport, typed view and depth subresource. | The DX11 Referee selects the current member. The evaluator and motion judge share the verified scene history while the screen judge retains the individual physical proof. A different view, lifetime or incomplete command list suspends that decision. More than two competing scene owners still need a qualified rule. |
| Scope, bow, menu, resize or brief frame loss changes the route | Count eligible transitions separately from output matches. Distinguish a deliberately disabled enhancement, a missing submission and a presented input. Reset comparisons at a history reset or a swap-chain change. | Keep ordinary delivery during qualification. A contradicted proof loses steering and can earn a fresh one after a bounded cooldown. Old rollback votes expire at history resets. DX12 tracks inconclusive tests separately from measured bypass. |
| An edge, reflection, fog layer or HUD looks wrong on only part of the screen | Both input-favoring and output-favoring textured regions within the same registered frame. Distinguish this from whole-frame alternation. Compare input, reconstruction and present in chronological order. | Repeated mixed screens produce `check_composite`. Such samples never supply a whole-route rollback vote. On-screen instrumentation still samples sparse regions. Identifying a small offending layer that the probes miss requires a targeted sample and an executed writer/reader trace. |
| Stale, wrong-sized, reversed, aliased or unshifted depth | Establish the depth's ownership, subresource, depth direction, clear/write history and read ordering. Compare the actual raster jitter with the buffer that DLAA and the lighting shader consume. | An incompatible input remains unqualified. The existing depth correction uses the current proven writer and restores the game's bindings. A compute write, opaque deferred list or unknown predication cannot be treated as a witnessed scene write. |
| False motion on a still object, missing mover motion, swaying or wrong jitter | Compare against the previous adjacent input in the same logical scene. Test reprojection against stillness and alternate vector scales. Check where the artifact first appears across input, output and screen. | Preserve the correct placement while investigating inputs and presets. The current Referee can identify badly explained motion or contradictory jitter and report what it measured. It has no counterfactual test that can select a better motion field or model in a running game. Fable's isolated NGX replay supports that analysis outside gameplay. |
| Incomplete GPU evidence, lost resources or high overhead | Resource identity and leases, exact frame pairing, readback completion and enough useful pixels. | Keep work asynchronous and bounded. Unknown evidence cannot promote a candidate or retire a proof. Measure live CPU/GPU costs against a matched game run before changing the cadence or broadening observation. |

## What changed in the build

- An every-other-frame DX12 marker was compatible with natural even/odd lighting. Its three regions now use the existing eight-pattern DX11 sequence and require an uninterrupted direction of response to at least four transitions in two regions. A failed or silent readback produces uncertainty. The RTV marker path also skips unused UAV creation.
- Temporary changes used to blacklist native DX11 readers until the route reset. The Referee now delays repeat trials with bounded backoff. A proven alternative can keep running. A reader that returns earns fresh proof. Provisional DX12 crossings likewise cool down, with different handling for an inconclusive test and a measured screen bypass.
- The rotating native DX11 route used a shared history in DLAA but also used physical proof equality in the motion judge. This excluded exactly the inter-buffer frame pairs the fix needed to inspect. The motion judge now accepts the same verified scene generation and depth on adjacent frames. Screen judgments stay scoped to each reader.
- The rotating route checks the source writer's actual view and viewport, rather than inferring them from the other buffer. Explicit updates and incomplete or reused deferred-list records cannot supply a clean rotating proof. A scene reset drops rollback evidence and prevents a worker scoring an older frame from reinstating it.
- Local screen evidence and whole-screen recovery now have different actions. A strongly split screen triggers compositor diagnosis while leaving the current route in place. A route proved before a history reset cannot win a post-reset comparison.

## What still separates this from automatic repair in unfamiliar engines

The limiting dependency is visibility into execution. Automatic repair needs a bounded way to trace an unfamiliar consumer from the actual submitted writer through its downstream composites. That trace must associate every result with the real frame and the correct swap chain, including acceptance of nonblocking Present calls. It then needs to trial one alternative at a time against a held-out window, with several registered regions, equivalent frame history and an immediate fallback. A small change that never reaches the screen tells the Referee about that candidate only. An unresolved or missing sample should lead to a better observation, not a guess about the engine.

The next two concrete profiles are a compute/deferred compositor with execution and subresource evidence, and a local temporal comparison that can trigger a short, targeted burst around the region that disagrees. The second should include adjacent inputs, reconstructions and presentations, report which stage first introduces the artifact, and keep quality changes preview-only until they have a verified replacement. These are gaps in the current build. The automated fixtures exercise the supported rules without establishing a new in-game result.

## November 21 update — What happens next during play

These decisions run with Referee enabled on the native DX11 and DX12 DLAA paths. Each adapter observes its own graphics commands. Both use the same screen comparisons, placement trials and stage-recovery rules.

| What the program observes | What it does |
|---|---|
| An unfamiliar scene, or a previously useful draw has moved | Keep the ordinary path available. The adapter follows executed writers and readers and challenges an available alternative against the presented image. A missed or ambiguous observation alone cannot prove that a replacement is better. |
| Two textures exchange lighting roles | Qualify both owners on the screen and follow the observed role. A timed comparison can establish a benefit when swaps are irregular. The faster admission for alternate-frame lighting also requires six agreeing transitions, including two in each direction on separate frame pairs. The depth buffer alone cannot identify the scene that produced the signature. |
| DLAA arrives, but a region still flashes | Trace the same region through scene input, reconstruction and presentation. On the input side, compare subdued Bloom or current-frame ambient shading if that effect ran. During reconstruction, compare camera motion without the residual or directly measured motion in place of the fitted field when the corresponding supplier ran. After reconstruction, compare reduced sharpening if sharpening ran. |
| A candidate frame shows the untreated picture | Roll back an applied candidate on a verified screen bypass. A missing optional motion score cannot hold up that decision. With renewed evidence, the next eligible tool gets its own comparison. An unknown screen vote alone cannot rule a tool out. |
| A menu or a different view interrupts a comparison | Compare damage using ordinary pictures from the qualifying scene and matching view. The set of matching reference pictures travels with the sliding window. Once a different view leaves that window it stops affecting the verdict. |
| A previously harmful lighting placement returns | Remember up to eight proved harmful placement scopes within one presentation. The ordinary, timed and immediate admission paths respect that history. A different scene generation can qualify on its own. Presentation changes and Referee opt-out clear this memory. Stage-tool exclusions and inconclusive retries retain their existing separate rules. |
| No observable stage or runnable correction fits | Continue observing while the qualified renderer handles available frames. Keep a proved improvement while testing a smaller residual. A motion or jitter diagnostic on its own does not authorize guessing an input convention. |

The fast lighting decision applies to an independently proved pair. Three or more ambiguous scene owners, an unobserved compositor, or a real motion source that no adapter can supply still require additional acquisition support. The logic makes no game-name checks. Its memory is bounded to the active presentation.
