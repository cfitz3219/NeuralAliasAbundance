# Material preparation and runtime handoff, v1

Owner: Astra (format/preparation), Fable (acquisition/bindings). Implemented alongside Cort's approved 2026-11-14 combined plan. The first tool operates outside the game. This contract enables Fable's fixture marker and plain-upscale baseline without waiting for the coordinated generator.

Each immutable cache directory is named by `entry_key`, a lowercase SHA256 of the canonical JSON recipe (sorted object keys, compact separators, ASCII JSON, no NaN). Recipe fields: schema version, material id, generator id/version, settings, seed, each source's content digest/identity domain/observed mip and typed-view facts, plus declared semantic interpretation. Store this recipe verbatim as `recipe` in `manifest.json`; hash exactly that object. No timestamps, absolute paths, GPU addresses or transient binding slots in the key. Same content under different map interpretation is a different recipe.

`manifest.json` fields: `schema_version` (1), `material_id`, `entry_key`, `algorithm`, `algorithm_version`, `settings`, `seed`, `fixture`, `recipe`, `maps`, `payload_bytes`. Each map contains `id`, `role` (`base_color`, `normal`, `roughness`, `packed`), `source`, `channels` (four semantic strings), `encoding`, `address` (`wrap`/`clamp`), `dxgi_format`, `width`, `height`, `file` (relative DDS leaf), `sha256`, `mips`. Source fields match `Source` in `src/materials/record.hpp`; zero view format means unqualified, not guessed. Complete means the stated observed range only. `mips` entries have level, width, height, offset, row_pitch and byte_size. Offsets include the 148-byte DDS+DX10 header. All payloads are 2D, one slice, one sample in v1. Full mip chains descend by floor-halving to 1x1.

First outputs: BC7_UNORM_SRGB (99) for base colour, BC5_UNORM (83) for positive-Z tangent normal XY, BC4_UNORM (80) for perceptual roughness. Input conventions must be explicitly converted before generation. The normal XY direction is preserved from the source; no assumption that every game's green channel has the same sign. Packed destination maps require repacking and a proved shader interpretation by the runtime owner; do not bind a BC4 roughness image to an unrelated packed slot. Larger prepared dimensions are allowed by the file format, not automatically qualified for a particular shader. The first generator preserves dimensions.

Writer creates all maps in a private temporary directory, checks bytes/headers/hashes, writes the manifest last, and renames the completed directory into the content cache. Never mutate an existing entry. Incomplete directories have no published manifest and are not candidates. The runtime loads one record/map set, then publishes it as a unit under its own exact recording/submission lifetime policy. Preparing a valid record is not proof of bound shader use.

The generation source may be file bytes (prototype inputs) or a normalized owned subresource dump (runtime census). Identity domains cannot be interchanged. Source association with actual game SRVs is the acquisition owner's job; no fixture filename or content key automatically identifies a game material. Source mutation, changed mip ranges, role decoding, settings or generator version produce a different entry. Runtime maps process-local resource generations to these immutable entries and accounts for old submitted versions separately.

No extra runtime inference dependency, no game file replacement. Models/weights and generated game assets are not committed. Fable's plain-upscale baseline can emit the same record with its own algorithm id and include only the qualified colour map. Coordinated outputs can add maps without changing the publication unit. A shared viewer reads three candidates with the same semantic roles; missing baseline normal/roughness use the original maps, never the coordinated candidate's maps.
