# Useful open-source additions — 5 November 2026

Research requested by Cort; not an instruction to install all of these. Primary repositories, actual license texts and relevant source files were checked. Recommendations below are engineering judgments about NeuralAlias, not measured integrations or promises of universal game compatibility. No new dependency or effect was added for this research.

## Best opportunities for this program

| Project | Verified license | Concrete use in NeuralAlias | Practical result and fit |
| --- | --- | --- | --- |
| [Tracy](https://github.com/wolfpld/tracy) | [BSD-3-Clause](https://github.com/wolfpld/tracy/blob/master/LICENSE) | On-demand CPU/GPU profiling of our hook callbacks, locks, descriptor tracking, camera work and GPU passes. Start with bounded zones around existing major stages. | Locate the expensive stage and thread contention directly. A developer instrument, not an image filter or automatic speed boost. Leave detailed instrumentation out of normal release operation. |
| [Adaptive-sharpen](https://github.com/bacondither/Adaptive-sharpen) | [BSD-2-Clause](https://github.com/bacondither/Adaptive-sharpen/blob/master/LICENSE) | Comparison/reference for soft-edge emphasis and reduced sharpening of already sharp edges/flat areas. Our RCAS already has separately limited bright/dark overshoot inspired by this project (`live_dlaa.cpp`, soft halo control); that benefit is not a new integration to count twice. | Further ideas need comparison against our existing protection, not another stacked full sharpener. Original shader expects gamma-corrected input and a floating-point intermediate; retain correct HDR/SDR interpretation. Worth an offline comparison, lower priority than the wholly new Deband effect. |
| [Deband by haasn / JPulowski](https://github.com/crosire/reshade-shaders/blob/slim/Shaders/Deband.fx) | Permissive MIT grant in the shader, with author-credit notice | Optional post-reconstruction cleanup of visible gradient bands in skies/fog. Reuse its flat-region/chroma analysis and limited dithering, ported into our existing HLSL pass machinery. | A directly visible new enhancement. Preserve real detail using the detector, and keep protected HUD outside the effect. Not a temporal motion/jitter repair. Does not require distributing ReShade after a native port. |
| [RenoDX](https://github.com/clshortfuse/renodx) | [MIT](https://github.com/clshortfuse/renodx/blob/main/LICENSE) | Adapt selected shader/pipeline/resource/format/state utilities. Actual reviewed files: [shader.hpp](https://github.com/clshortfuse/renodx/blob/main/src/utils/shader.hpp), [pipeline.hpp](https://github.com/clshortfuse/renodx/blob/main/src/utils/pipeline.hpp), [swapchain.hpp](https://github.com/clshortfuse/renodx/blob/main/src/utils/swapchain.hpp). | Mature examples of replacement revision tracking, pipeline-layout handling and swapchain/resource state. Useful for broader compatibility. It uses ReShade's API, so the relevant pieces need a bridge to our existing observer; adopting its frontend is unnecessary. Shader hashes identify programs but do not independently prove they draw HUD. |
| [NVIDIA ShaderMake](https://github.com/NVIDIA-RTX/ShaderMake) | [MIT](https://github.com/NVIDIA-RTX/ShaderMake/blob/main/LICENSE.txt) | Build our known HLSL variants ahead of time with FXC/DXC, embed binaries/header blobs and track source/include/compiler changes. | Less runtime preparation of our own shader bytecode and consistent variant packaging. Complements existing background preparation. It cannot precompile an unknown game's future PSOs or eliminate all driver pipeline compilation. |
| [Intel PresentMon](https://github.com/GameTechDev/PresentMon) | MIT, [README license](https://github.com/GameTechDev/PresentMon#license) | Reuse its ETW collection/analysis library or API for optional performance capture and installer support diagnostics. We already use external PresentMon recordings; this is a possible product/library integration of that established measurement. | Consistent CPU/GPU/display timing and frame-pacing reports across vendors. Pair with our own frame-identity receipts; presentation events alone do not establish that NR ran on a specific real frame. |
| [AMD GPU Reshape](https://github.com/GPUOpen-Tools/GPU-Reshape) | [MIT](https://github.com/GPUOpen-Tools/GPU-Reshape/blob/main/License.md) | A development tool for actual shader descriptor indexing, bounds, initialization and concurrency errors. [AMD description](https://gpuopen.com/gpu-reshape/) supports D3D12/Vulkan and all GPU vendors. | Useful when a normal API check cannot identify which shader access is wrong. Run on a focused fixture first; not a new always-on validation layer in a shipping game. |
| [Microsoft DirectXMath](https://github.com/microsoft/DirectXMath) | [MIT](https://github.com/microsoft/DirectXMath/blob/main/LICENSE) | SIMD matrix/vector implementations for any camera/scanner math that profiling identifies as material. | Small targeted reuse, with our matrix-layout and convention tests retained. Does not remove the cost of interception, memory lookup or locking. |
| [AMD FidelityFX SPD](https://github.com/GPUOpen-Effects/FidelityFX-SPD) | [MIT](https://github.com/GPUOpen-Effects/FidelityFX-SPD/blob/master/LICENSE) | Shared downsampling where several consumers genuinely need a mip pyramid. Existing optical-flow dependency already vendors SPD for its own luminance pyramid. | Reuse that existing component rather than another pyramid algorithm. Not automatically a gain for our current two-direction Bloom blur, and do not generate unused mips. [Primary description](https://gpuopen.com/fidelityfx-spd/). |
| [AMD FSR UI composition / scheduling](https://gpuopen.com/manuals/fidelityfx_sdk/techniques/super-resolution-interpolation/) | The inspected [SDK v1.1.4 source](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/tree/v1.1.4) and [license](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/blob/v1.1.4/docs/license.md) are MIT | Reference/selected code for distinct UI callback, UI-texture and HUD-less-image paths and their real/generated presentation scheduling. | Strengthen composition contracts once HUD source is available. It does not automatically discover HUD from an arbitrary completed image; avoid confusing composition with acquisition. Pin inspected MIT components rather than assuming every file in the latest SDK has that license. |

Priority depends on the intended result. For overhead, start with Tracy. For a visible image addition, Deband is the cleanest separate feature. For reusable graphics integration, inspect RenoDX's small utilities. Those are the top three new opportunities. ShaderMake is a sensible build improvement. Adaptive-sharpen remains a relevant comparison, but we already borrowed one of its useful ideas. None requires replacing our discovery, frame identity, motion, DLSS/NR or existing GPU ownership core.

## What we already have

The repository already contains or integrates RCAS/NIS, XeGTAO, AMD optical flow including SPD, Breadcrumbs, Donut Bloom, NVRHI, D3D12MA and Taskflow. A second AO library or second general renderer is not a new capability by itself. Taskflow handles bounded preparation work; D3D12MA pools scratch backing. Existing code and measurements should decide further reuse, not the library's brand.

The separate same-day NVRHI measurement illustrates this rule: the current native Bloom CPU path was 21.628 us versus 29.066 us through our wrapper, equal pixels. The NVRHI option was removed and automatic selection retains native for these paths. The shared allocator/background work remains active. See GPU-AUTOMATIC-AND-OPUS-REVIEW-20261105.md for exact scope and evidence.

## Marty and other attractive-looking repositories

The inspected [qUINT sharpen file](https://github.com/martymcmodding/qUINT/blob/master/Shaders/qUINT_sharp.fx) reserves copyright, and [qUINT deband](https://github.com/martymcmodding/qUINT/blob/master/Shaders/qUINT_deband.fx) explicitly prohibits unauthorized copying. Publicly readable source is not itself permission to incorporate it. These specific files are not approved copy sources. General image-processing ideas can inform an independent implementation, or permission can be requested. The permissive Adaptive-sharpen/Deband projects above give concrete alternatives now.

[NVIDIA NRD](https://github.com/NVIDIA-RTX/NRD) is a ray-tracing denoiser with a specific SDK license and required lighting/normal/roughness/depth inputs. It is not the DLSS NR model and not a general final-image cleanup filter. RTXDI/RTXGI similarly need lighting/scene data that cannot be assumed from a final colour image. Interesting future references, but not immediate drop-in enhancements to promise here. DLSS model binaries themselves are not open-source just because integration headers/examples are public.

Preserve each upstream notice and pin the exact files at implementation time. No game testing, deployment, new effect integration or broad renderer migration was performed during this research.
